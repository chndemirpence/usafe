Recipient: SignPath Foundation, through its official application channel.
Maintainer: Cihan Demirpençe, repository owner chndemirpence.

Subject: USAFE Connect — open-source Windows code-signing eligibility

Hello SignPath Foundation team,

I maintain USAFE Connect, an MIT-licensed Windows desktop controller that helps
users establish a Tor browsing session through Snowflake, obfs4 or a supplied
bridge. It starts official, unmodified Tor components and Tor Browser. Its
purpose is internet access under censorship, with clear connection recovery and
English/Turkish guidance. It does not scan for exploitable vulnerabilities or
modify Windows' system proxy.

Source: https://github.com/chndemirpence/usafe
Current release: https://github.com/chndemirpence/usafe/releases/tag/usafe-connect-v0.1.2
Download entry: https://www.calcoras.com/usafe/#connect

The controller is packaged with PyInstaller. We verify official upstream Tor
archive signatures/checksums and preserve upstream notices. We would request
signing only for our own controller executable, leaving upstream binaries
unchanged. The current public controller executable is unsigned.

Could you confirm whether this type of censorship-circumvention controller can
be considered under the Foundation's eligibility policy? If eligible, we would
like to establish the required source-linked build, artifact restrictions,
manual approval process and code-signing policy for the project. Please let us
know which project evidence and build-integration steps you require.

Best regards,
Cihan Demirpençe
USAFE / ArgoDelta
